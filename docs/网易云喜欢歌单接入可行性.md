# 网易云音乐「我喜欢的音乐」接入可行性与技术方案

## 1. 调研结论

**结论：完全可行。**

- **上游能力**：运行于生产宿主机的 `Binaryify/NeteaseCloudMusicApi`（版本 4.27.0）原生支持用户歌单查询、歌单详情与分页曲目拉取。
- **定位方式**：通过网易云官方标准字段 `specialType == 5` 与所有者校验，可 100% 稳定定位当前账号的系统预置喜欢歌单，不依赖硬编码 Playlist ID，不依赖歌单中文名匹配。
- **播放复用**：车机端播放链路（ExoPlayer + 后端动态缓存串流 `/api/v1/music/netease/stream/{id}`）以及 iOS 控制（播控/音量/进度/循环）与 Stage 1 完全一致，无需任何改动。
- **范围限制**：本次仅完成能力核对与方案调研，**未改动任何 iOS 客户端代码，未增加或部署任何后端路由**。

## 3. 专属「我喜欢的音乐」定位策略

### 3.1 常见误区与隐患
- **硬编码固定 Playlist ID**：每个网易云用户的喜欢歌单 ID 皆随机生成，硬编码无法支持账号换绑或多环境迁移。
- **匹配中文名称 `name == "我喜欢的音乐"`**：脆弱不可靠。当客户端系统语言为英文时歌单显示为英文；若用户自建或收藏了同名歌单，极易混淆。

### 3.2 可靠定位算法
利用网易云服务端的内置类型标记：
1. 调用 `/user/playlist?uid={current_uid}`；
2. 过滤符合以下条件的歌单：
   - `specialType == 5`（网易云规范中用于标记账号默认“我喜欢的音乐”歌单）；
   - `creator.userId == current_uid`（确保为当前登录账号创建）。
3. 实测结果：在 R9000P 当前登录会话下只读核对，成功准确定位出 1 个 `specialType == 5` 的专属歌单，当前包含 746 首曲目，排序为第 0 个歌单。

## 4. 关键限制与安全边界

### 4.1 列表可见不等于全部可播放
- **版权与地域限制**：部分歌曲由于版权下架或地域限制，其 `privilege.st < 0`（置灰）。请求 CDN URL 时将返回空或失效链接。
- **VIP 独占曲目**：歌曲 `fee == 1` 或 `fee == 8`。若登录账号非有效 VIP，上游仅返回 30 秒免费试听片段或空 URL。
- **安全保障**：后端现有的 `/netease/stream/{song_id}` 具备非音频响应拦截机制，iOS 端在发起 `playTrack` 前已有 `ensureOnlinePlayable` HEAD 探测保护，遇到不可播歌曲会及时提示用户而不会使车机端崩溃。

### 4.2 账号权限隔离边界
- **全局单账号现状**：目前后端采用全局单实例 Cookie 存储（`netease_cookie.json`），属于服务器 Owner 个人账号。**当前系统不支持多用户各自独立绑定网易云账号**，不能假装支持多租户。
- **访问控制规则**：
  - 「我喜欢的音乐」包含服务 Owner 私人偏好，属于敏感数据；
  - 必须严格配置 `require_admin_or_legacy_phone` 权限守卫，仅允许管理员（或 legacy 凭据）拉取；
  - 普通注册用户（`role == "user"`）只能使用公用搜索，严禁未经授权越权读取 Owner 个人收藏。
